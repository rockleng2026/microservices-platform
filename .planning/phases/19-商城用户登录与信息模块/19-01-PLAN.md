## 核心问题深度分析

> 用户反馈：微信登录修改个人信息后，memberId 和 UserId 使用存在混淆，导致前端登录后编辑用户信息与获取用户信息不一致。

### 问题一：mall_member.id vs mall_member.userId — 职责不清

**现状：**
```java
// AuthController.java:123, 213 - 新建会员时设置 userId
member.setUserId(System.currentTimeMillis()); // ← 问题：滥用时间戳作为ID

// AuthController.java:131 - 生成 token 时用的是 member.getId()
String token = "WX_" + member.getId() + "_" + UUID.randomUUID()...
```

**分析：**
- `mall_member.id` — AUTO_INCREMENT 主键，真正的主键
- `mall_member.userId` — 冗余字段，用 `System.currentTimeMillis()` 生成，非唯一且会冲突
- Token 中存储的是 `member.getId()`（主键），但查询时有时用 `getByUserId()` 有时用 `getById()`
- **结论**：`userId` 字段是冗余的，历史遗留问题，应该统一使用 `id` 作为所有表的外键关联目标

**业务表中的 userId 关联目标混乱：**
| 表名 | 字段 | 实际存储的值 | 关联目标 |
|------|------|-------------|----------|
| mall_order.userId | BIGINT | member.getId() (主键) | mall_member.id |
| mall_cart.userId | BIGINT | member.getId() (主键) | mall_member.id |
| mall_coupon.userId | BIGINT | member.getId() (主键) | mall_member.id |
| mall_points_account.userId | BIGINT | ? (部分硬编码为1L) | mall_member.id |

---

### 问题二：各业务表（积分/订单/购物车）的 userId 关联目标不明确

**代码证据：**
```java
// MarketingServiceImpl.java:450
.eq(MallPointsAccount::getUserId, 1L) // TODO: get real userId

// MarketingServiceImpl.java:455
account.setUserId(1L); // TODO
```

**问题：** 积分账户的 userId 在某些地方硬编码为 1L，导致积分账户与真实会员不对应。

**建议修复：**
- 统一使用 `mall_member.id` 作为所有业务表的外键
- 删除 `mall_member.userId` 字段（或保留作为第三方系统关联字段，但不对其建立外键约束）
- 积分账户创建时，应使用当前登录会员的 `member.getId()`

---

### 问题三：Token 格式和解析流程需要与表设计对齐

**当前 Token 格式：**
```java
// AuthController.java:131, 166, 220
"WX_" + member.getId() + "_" + UUID.randomUUID().toString().replace("-", "").substring(0, 32)
"TOKEN_" + member.getId() + "_" + UUID.randomUUID().toString().replace("-", "").substring(0, 32)
```

**网关解析 (WxTokenUserIdFilter)：**
- 从 Authorization header 提取 token
- 解析 `PREFIX_<userId>_<hex>` 格式，提取 userId
- 设置 `x-user-id` header 传给下游服务

**问题：**
1. Token 中存储的是 `member.getId()`，但字段名叫 `userId`，命名混乱
2. 网关解析时直接提取第二段作为 `userId`，实际上拿到的是 `mall_member.id`
3. 下游服务用这个 `userId` 调用 `memberService.getById(userId)` 查询，但实际上应该叫 `memberId`

**建议修复：**
- Token 中明确存储 `memberId`（即 mall_member.id）
- 网关设置 header 为 `x-member-id` 或保持 `x-user-id` 但注释说明实际是 memberId
- 服务层方法命名统一：`getMemberById()` 而非 `getByUserId`

---

### 问题四：/member/info 查询逻辑与积分账户创建逻辑不一致

**UserController.getUserInfo() — 返回硬编码假数据：**
```java
// UserController.java:21-28
public Result<Map<String, Object>> getUserInfo() {
    Long userId = getCurrentUserId(); // ← 来自 token 解析，实际是 member.id
    Map<String, Object> userInfo = new HashMap<>();
    userInfo.put("userId", userId);
    userInfo.put("nickname", "测试用户");     // ← 假数据！
    userInfo.put("avatar", "/images/avatar/default.jpg"); // ← 假数据！
    userInfo.put("phone", "13800138000");    // ← 假数据！
    return Result.succeed(userInfo);
}
```

**MallMemberServiceImpl 有真实查询方法但未被调用：**
```java
// MallMemberServiceImpl.java:24
wrapper.eq(MallMember::getUserId, userId);  // ← 但 UserController 并未调用此方法

// MallMemberServiceImpl.java:65
member.setUserId(userId); // 更新会员时使用 userId
```

**积分账户创建时 userId 不确定：**
```java
// MarketingServiceImpl.java:450, 455
.eq(MallPointsAccount::getUserId, 1L) // TODO: get real userId
account.setUserId(1L); // TODO
```

**问题链：**
```
Token (存 member.id) 
  → 网关解析出 userId (实为 member.id)
  → UserContext.getCurrentUserId() 返回这个值
  → getUserInfo() 用这个值查询，但返回的是假数据
  → 积分账户创建时用硬编码 1L，与当前登录用户无关
```

**修复方案：**
1. `UserController.getUserInfo()` 应调用 `mallMemberService.getById(userId)` 获取真实数据
2. 积分账户创建时，使用 `UserContext.getCurrentUserId()` 获取真实的 memberId
3. 统一方法命名：`getByMemberId()` 替代 `getByUserId()`
