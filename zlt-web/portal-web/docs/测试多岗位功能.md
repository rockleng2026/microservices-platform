# Portal 多岗位功能测试指南

## 测试环境准备

### 1. 数据库准备
```sql
-- 1. 在employee表中为测试用户添加副岗位
UPDATE employee 
SET secondary_position_ids = '2,3' 
WHERE id = 1;  -- 假设员工ID为1

-- 2. 确保workposition表中有足够的测试岗位
INSERT INTO workposition (name, short_name, department_id, status, tenant_id) VALUES
('测试主岗位', '主岗', 1, 1, 'default'),
('测试副岗位1', '副岗1', 1, 1, 'default'),
('测试副岗位2', '副岗2', 1, 1, 'default');

-- 3. 确保用户关联到员工
UPDATE users SET employee_id = 1 WHERE id = 1;  -- 假设用户ID为1
```

### 2. 后端服务启动
确保以下服务正常运行：
- Gateway网关服务 (端口9900)
- Organization组织服务 (端口8765)
- Auth认证服务 (端口8762)

### 3. 前端服务启动
```bash
cd zlt-web/portal-web
npm install
npm start
```

## 功能测试步骤

### 1. 登录测试
1. 打开浏览器访问 `http://localhost:3000`
2. 使用测试账号登录
3. 检查控制台是否有以下日志：
   ```
   UserMenu: 开始加载用户数据...
   UserMenu: 获取用户信息响应: {resp_code: 0, datas: {...}}
   UserMenu: 开始加载用户岗位信息, userId: 1
   UserMenu: 岗位信息响应: {success: true, data: [...]}
   ```

### 2. 多岗位显示测试
1. 登录后检查右上角用户信息区域
2. 应该能看到：
   - 用户头像和姓名
   - 当前岗位名称
   - 岗位选择器（如果有多个岗位）
3. 检查岗位选择器下拉列表：
   - 主岗位应该显示 "(主岗位)" 标识
   - 副岗位应该显示 "(副岗位)" 标识

### 3. 岗位切换测试
1. 点击岗位选择器下拉菜单
2. 选择不同的岗位
3. 检查以下行为：
   - 显示切换成功的消息提示
   - 当前岗位名称更新
   - 左侧菜单权限自动更新
   - 控制台输出岗位切换日志

### 4. 权限验证测试
1. 切换到不同岗位
2. 检查左侧菜单是否根据岗位权限变化
3. 验证只有当前岗位有权限的菜单才显示

### 5. API测试
使用Postman或curl测试API：

```bash
# 1. 获取用户岗位列表
curl -X GET "http://localhost:9900/api-portal/users/positions" \
  -H "Authorization: Bearer YOUR_TOKEN"

# 2. 切换用户岗位
curl -X POST "http://localhost:9900/api-portal/users/switch-position?positionId=2" \
  -H "Authorization: Bearer YOUR_TOKEN"

# 3. 获取当前用户信息
curl -X GET "http://localhost:9900/api-portal/users/current" \
  -H "Authorization: Bearer YOUR_TOKEN"

# 4. 获取用户菜单权限
curl -X GET "http://localhost:9900/api-portal/users/menus" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## 错误排查

### 1. 岗位列表为空
检查项：
- 数据库中employee.secondary_position_ids字段是否有数据
- workposition表中岗位状态是否正常(status=1, delflag=0)
- 用户是否正确关联到员工(users.employee_id)

### 2. 岗位切换失败
检查项：
- 目标岗位是否在用户的岗位列表中
- 数据库连接是否正常
- 事务是否正确提交

### 3. 权限更新不及时
检查项：
- 岗位切换后是否触发了菜单重新加载
- 缓存是否正确清理
- 全局事件是否正确触发

### 4. 常见错误日志
```
ERROR: 获取岗位信息失败 - 检查数据库连接和表结构
ERROR: 岗位切换失败 - 检查权限验证逻辑
ERROR: 菜单权限获取失败 - 检查权限服务是否正常
```

## 性能测试

### 1. 响应时间要求
- 岗位列表获取：< 500ms
- 岗位切换：< 1s
- 菜单权限加载：< 800ms

### 2. 并发测试
使用JMeter或其他工具测试：
- 100个并发用户同时切换岗位
- 验证系统稳定性和响应时间

### 3. 内存使用
监控前端页面内存使用，确保无内存泄漏。

## 安全测试

### 1. 权限验证
- 用户只能切换到自己有权限的岗位
- 不能通过API直接切换到其他用户的岗位
- 菜单权限严格按照岗位权限控制

### 2. 数据安全
- 敏感信息不在前端暴露
- API调用需要有效的认证token
- 防止SQL注入和XSS攻击
