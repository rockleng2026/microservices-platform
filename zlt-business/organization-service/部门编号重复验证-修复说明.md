# 部门编号重复验证 - 修复说明

## 问题描述

用户在编辑部门时遇到"部门编号已存在"的错误，即使保持部门编号不变也会报错。这是因为后端验证逻辑没有正确排除当前编辑的部门本身。

## 问题原因

### 1. 前端操作类型传递问题
之前前端在编辑操作时未正确设置 `operationType` 为 `"edit"`，导致后端无法区分新增和编辑操作。

### 2. 后端验证逻辑不够精确
原来的验证逻辑中，判断编辑操作的条件不够准确：
```java
// 原来的逻辑
boolean isEdit = saveDTO.getId() != null || "edit".equals(saveDTO.getOperationType());
```

这个逻辑存在问题，因为在某些情况下会误判。

## 修复方案

### 1. 前端修复（已完成）
在 `index.tsx` 中确保编辑操作正确设置 `modalType`：
```typescript
// 处理编辑（详情面板操作）
const handleEdit = () => {
  setModalType('edit'); // 确保设置为编辑模式
  setShowEditForm(true);
};

// 处理编辑（树节点操作）
const handleEditFromTree = (deptId: string, e: any) => {
  setModalType('edit'); // 确保设置为编辑模式
  setShowEditForm(true);
};
```

在表单提交时传递正确的操作类型：
```typescript
// 根据modalType设置正确的操作类型
if (modalType === 'edit' && selectedDept) {
  submitData.operationType = 'edit'; // 明确标识这是编辑操作
} else {
  submitData.operationType = 'add'; // 明确标识这是新增操作
}
```

### 2. 后端修复（本次完成）

#### 修复验证逻辑
重新设计了 `validateDepartmentData` 方法中的操作类型判断逻辑：

```java
// 精确判断是新增还是编辑操作
// 1. 优先使用operationType字段判断
// 2. 其次使用ID是否存在判断
boolean isEdit = false;
Long excludeId = null;

if ("edit".equals(saveDTO.getOperationType())) {
    // 明确标识为编辑操作
    isEdit = true;
    excludeId = saveDTO.getId();
    if (excludeId == null) {
        log.warn("编辑操作但未提供部门ID，可能存在数据异常");
    }
} else if ("add".equals(saveDTO.getOperationType())) {
    // 明确标识为新增操作
    isEdit = false;
    excludeId = null;
} else {
    // 未明确标识操作类型，根据ID判断
    if (saveDTO.getId() != null) {
        isEdit = true;
        excludeId = saveDTO.getId();
        log.info("未标识操作类型，根据ID判断为编辑操作");
    } else {
        isEdit = false;
        excludeId = null;
        log.info("未标识操作类型，根据ID判断为新增操作");
    }
}
```

#### 增强部门编号验证
改进了部门编号重复检查的逻辑：

```java
// 检查部门编号是否重复
if (StrUtil.isNotBlank(saveDTO.getDepNo())) {
    boolean depNoExists = existsByDepNo(saveDTO.getDepNo(), excludeId);
    
    if (depNoExists) {
        if (isEdit) {
            log.warn("编辑部门时部门编号重复 - 编号: {}, 排除ID: {}, 仍然重复", 
                     saveDTO.getDepNo(), excludeId);
            throw new RuntimeException("部门编号已存在");
        } else {
            log.warn("新增部门时部门编号重复 - 编号: {}", saveDTO.getDepNo());
            throw new RuntimeException("部门编号已存在");
        }
    } else {
        if (isEdit) {
            log.info("编辑部门编号验证通过 - 编号: {}, 排除ID: {}", 
                     saveDTO.getDepNo(), excludeId);
        } else {
            log.info("新增部门编号验证通过 - 编号: {}", saveDTO.getDepNo());
        }
    }
}
```

## 关键技术点

### 1. 操作类型优先级
1. **第一优先级**：`operationType` 字段（"edit" 或 "add"）
2. **第二优先级**：`id` 字段是否存在
3. **兜底策略**：详细的日志记录帮助问题排查

### 2. 排除逻辑
- **编辑操作**：`existsByDepNo(depNo, excludeId)` - 排除当前部门ID
- **新增操作**：`existsByDepNo(depNo, null)` - 检查所有部门

### 3. 日志增强
所有验证步骤都有详细的日志记录，包括：
- 操作类型判断过程
- 排除ID的设置
- 验证结果的详细说明
