# 在线商城平台（小程序+管理后台）需求与设计方案 (修订版)

> 文档版本: 1.1  
> 创建日期: 2026-05-08  
> 基于平台: central-platform v6.0.0  
> 业务命名: **mall-center** (通用商城)

---

## 1. 修正说明

- **名称修正**：原“硬件商城(hardware-mall)”更名为通用“商城(mall-center)”，以支持**IT硬件、其他实物商品**以及**虚拟商品（如技术文档、软件包）**的销售。
- **核心变更**：新增**商品类型**(实物/虚拟)概念，虚拟商品无需收货地址、无需物流发货、支付成功后自动交付资源。
- **数据库与服务名**：服务名由 `hardware-mall-center` 改为 `mall-center`，数据库表前缀保持 `mall_`，与方案兼容。

---

## 2. 项目概述 (更新)

### 2.1 项目简介

基于 central-platform 微服务架构，构建**通用在线商城**，可同时销售：

- 实物商品：服务器、CPU、内存、NAS、网络设备等 IT 硬件，以及任何需要物流的实体商品。
- 虚拟商品：技术文档、软件授权、API Key、电子资源包等，购买后即时获取下载链接或内容。

前端载体为**微信小程序**，后端提供**管理后台 Web**，支持通用电商运营。

### 2.2 核心特性 (补充)

- **商品类型区分**：实物商品走物流发货，虚拟商品即时交付资源链接/文件。
- **柔性订单流程**：虚拟商品支付后自动完成，无需收货地址。
- **资源管理**：虚拟商品可上传文件或输入外链，订单完成后向用户展示。
- 其他特性不变：SKU 多规格、库存安全扣减、微信支付、多租户兼容。

---

## 3. 需求分析 (更新)

### 3.1 功能模块补充

#### 3.1.1 小程序端

- **商品模块**：商品详情页需要显示**商品类型标签**（实物/虚拟），虚拟商品不显示运费相关，详情中可预览资源简介。
- **购物车**：虚拟商品允许加入购物车，但结算时不需要选择收货地址。
- **订单确认页**：根据商品类型动态调整：
  - 纯实物：需要收货地址。
  - 纯虚拟：隐藏地址选择，点击支付直接下单。
  - 混合购物车：前端应提示分开下单（或限制混合结算，推荐方案：不支持虚拟与实物同时购买，需拆单）。
- **订单详情**：
  - 实物：物流跟踪。
  - 虚拟：显示**下载链接/获取密钥**，支持复制或跳转。
- **支付成功后**：虚拟商品订单状态直接变为“已完成”，并提供访问资源的入口。

#### 3.1.2 管理后台

- **商品管理**：
  - 新增/编辑商品时可选择类型：**实物** / **虚拟**。
  - 虚拟商品额外字段：**资源文件**(上传到 OSS)、**外链地址**、**有效期**(可选)。
- **订单管理**：
  - 列表筛选增加**商品类型**。
  - 虚拟订单无“发货”操作按钮，可查看用户是否下载/查看（可选日志）。
- **库存管理**：虚拟商品库存可设为无限（不限制或库存字段忽略），或也可管理数量（如限量授权码）。
- **系统设置**：可配置默认虚拟商品交付模板。

## 4. 系统设计 (更新)

### 4.1 服务命名变更

- **模块名称**：`mall-center`
- **端口**：`7010`
- **数据库**：`cp_mall`
- **代码路径**：`zlt-business/mall-center/`

依赖关系不变。

### 4.2 数据库设计变更

#### 4.2.1 商品表 `mall_goods` 增加字段

```sql
ALTER TABLE `mall_goods` ADD COLUMN `goods_type` tinyint NOT NULL DEFAULT 1 COMMENT '商品类型:1实物,2虚拟';
ALTER TABLE `mall_goods` ADD COLUMN `virtual_url` varchar(500) COMMENT '虚拟资源链接';
-- 若需要资源文件，可复用一个文件ID关联 file-center 的存储
ALTER TABLE `mall_goods` ADD COLUMN `virtual_file_id` bigint COMMENT '虚拟资源文件ID(oss)';
ALTER TABLE `mall_goods` ADD COLUMN `virtual_expire` datetime COMMENT '资源有效期(空为永久)';
```

#### 4.2.2 订单表 `mall_order` 调整

- 虚拟订单可能没有 `delivery_id`，因此允许该字段为 NULL。
- 可以添加 `goods_type` 字段快速区分（冗余）。

```sql
ALTER TABLE `mall_order` MODIFY `delivery_id` bigint NULL;
ALTER TABLE `mall_order` ADD COLUMN `goods_type` tinyint DEFAULT 1 COMMENT '商品类型(冗余)';
-- 虚拟商品配送信息可空
ALTER TABLE `mall_order` MODIFY `address_snapshot` text NULL;
```

#### 4.2.3 订单状态流转调整

| 当前状态 | 实物           | 虚拟               |
| -------- | -------------- | ------------------ |
| 待付款   | ✓              | ✓                  |
| 待发货   | ✓              | ✗ (跳过)           |
| 已发货   | ✓              | ✗                  |
| 已完成   | ✓ (确认收货后) | ✓ (支付成功后自动) |
| 已取消   | ✓              | ✓                  |

虚拟商品支付成功回调后，直接更新订单状态为“已完成”，并生成资源交付记录（可记录在日志中）。

#### 4.2.4 新增资源交付记录表 (可选)

```sql
CREATE TABLE `mall_resource_delivery` (
    `id` bigint NOT NULL AUTO_INCREMENT,
    `tenant_id` varchar(32) NOT NULL,
    `order_id` bigint NOT NULL,
    `goods_id` bigint NOT NULL,
    `user_id` bigint NOT NULL,
    `url` varchar(500) COMMENT '交付链接',
    `create_time` datetime DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='虚拟商品交付记录';
```

#### 4.2.5 收货地址相关

收货地址表 `mall_user_address` 保留，虚拟商品不强制校验地址。

### 4.3 API 设计变更

#### 新增/修改接口

**商品详情** (`GET /goods/{id}`)  
返回增加字段：

```json
{
  "id": 1,
  "goodsType": 2,         // 1实物 2虚拟
  "virtualUrl": "...",    // 若已购买且为虚拟，可显示
  ...
}
```

**创建订单** (`POST /order`)  
请求体验证：

- 若订单中所有商品均为虚拟类型，则**可以不传收货地址ID**。
- 若包含实物，则必须传 `addressId`。

**支付回调**：  
虚拟商品订单成功后：

1. 订单状态 -> 已完成
2. 向 `mall_resource_delivery` 插入交付链接（或直接从商品表获取 `virtual_url`）
3. 可通过模板消息通知用户

**订单详情** (`GET /order/{id}`)  
返回数据若为虚拟商品已完成订单，附加：

```json
{
  "resources": [
    {
      "url": "https://oss.example.com/file.zip",
      "expire": "2026-06-08 00:00:00"
    }
  ]
}
```

**管理后台 - 发布/编辑商品** (`POST|PUT /admin/goods`)  
接受字段增加：`goodsType`, `virtualUrl`, `virtualFileId`, `virtualExpire`。

**管理后台 - 订单发货** (`POST /admin/order/{id}/deliver`)  
后端需校验 `order.goodsType = 1`，虚拟商品抛出异常，不允许发货。

### 4.4 库存处理

- 虚拟商品库存：若填写 `stock` 值 >0，则在创建订单时仍然预占库存并支付后扣除。若填写为 0，可设计为“无限制”，跳过库存校验（需代码实现 `stock = -1` 表示无限制）。
- 实物商品库存逻辑不变。

## 5. 实现调整清单

1. **服务名调整**：创建 `mall-center` 模块，包名 `com.central.mall`。
2. **数据库**：执行原 `mall_*` 表创建脚本，然后应用上述 ALTER 语句。
3. **代码**：
   - 实体类 `Goods` 增加 `goodsType`、`virtualUrl` 等字段。
   - `OrderServiceImpl.createOrder` 中判断商品类型集合：如果有实物则要求 `addressId`，否则可留空。
   - 支付回调处理中，若订单类型为虚拟则直接 `completeOrder`，并插入交付记录。
   - 管理后台商品表单增加类型切换，显示/隐藏虚拟信息字段。
4. **前端适配**：
   - 小程序：订单确认页根据购物车商品类型显示/隐藏地址区域；虚拟商品详情页增加资源下载按钮（订单完成后）。
   - 管理后台：商品列表显示“实物/虚拟”标签；订单列表和详情区分操作按钮。

---

## 6. 扩展性说明

- **更多商品类型**：若未来出现服务类商品（如人工运维服务），可扩展 `goods_type` 值，并增加相应订单状态处理。
- **会员与权限**：虚拟商品可限制购买权限（如 VIP），集成已有用户体系。
- **多租户**：保持 `tenant_id` 隔离，各商户可独立配置虚拟资源。

---

> 此方案保持与原平台架构的一致性，同时灵活支持**实物与虚拟**商品，避免“硬件”命名的局限性。所有设计均遵循 `central-platform` 的开发规范与微服务架构。
