# 部门编辑功能 - 后端修复说明

## 🎯 修复目标

解决部门编辑时"部门编号已存在"的错误问题，确保：
- 新增部门时正常验证编号唯一性
- 编辑部门时可以保持原编号不变
- 编辑部门时修改为其他已存在编号会报错

## 🔧 修复内容

### 1. DepartmentSaveDTO 增加操作类型标识

**文件**: `src/main/java/com/central/organization/model/dto/DepartmentSaveDTO.java`

**修改内容**:
```java
/**
 * 操作类型标识(前端传递，用于区分新增和编辑操作)
 * add: 新增操作
 * edit: 编辑操作
 */
private String operationType;
```

**作用**: 前端明确告知后端当前是新增还是编辑操作，避免仅依赖ID字段判断。

### 2. DepartmentServiceImpl 优化验证逻辑

**文件**: `src/main/java/com/central/organization/service/impl/DepartmentServiceImpl.java`

**关键修改** - `validateDepartmentData` 方法:

#### 原有问题代码:
```java
// ❌ 问题：编辑时也检查了自己
if (StrUtil.isNotBlank(saveDTO.getDepNo()) && 
    existsByDepNo(saveDTO.getDepNo(), saveDTO.getId())) {
    throw new RuntimeException("部门编号已存在");
}
```

#### 修复后代码:
```java
// ✅ 正确：根据操作类型区分验证逻辑
boolean isEdit = saveDTO.getId() != null || "edit".equals(saveDTO.getOperationType());

if (StrUtil.isNotBlank(saveDTO.getDepNo())) {
    if (isEdit) {
        // 编辑操作：检查除当前部门外是否有相同编号
        if (existsByDepNo(saveDTO.getDepNo(), saveDTO.getId())) {
            throw new RuntimeException("部门编号已存在");
        }
    } else {
        // 新增操作：检查是否有任何部门使用此编号
        if (existsByDepNo(saveDTO.getDepNo(), null)) {
            throw new RuntimeException("部门编号已存在");
        }
    }
}
```

### 3. DepartmentController 增加日志记录

**文件**: `src/main/java/com/central/organization/controller/DepartmentController.java`

**修改内容**:

```json
  "operationType": "add"
}
```
**期望结果**: ❌ 报错 "部门编号已存在"

**期望结果**: ✅ 保存成功（这是修复的关键场景）
