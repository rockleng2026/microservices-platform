# 最新版绩效考核系统设计方案
## 一、系统模块设计
### 1. 全局指标库管理
- **功能**：维护全公司可用的KPI指标，支持按部门分类、公式定义、数据源配置等。
- **子模块**：
    - 指标分类管理
    - KPI池维护
    - 数据源配置（对接CRM、GitLab、Jira等）
### 2. 考核周期管理
- **功能**：创建和管理考核周期，支持不同部门采用不同的考核模式。
- **子模块**：
    - 考核计划创建（支持选择模式：强管控/协商模式）
    - 销售部门：指标强制下发
    - 技术部门：计划协商中心
    - 计划监控看板
### 3. 绩效评定中心
- **功能**：员工和领导进行目标制定、自评、评分等操作。
- **子模块**：
    - 员工自评工作台（含个人计划创建）
    - 领导评分工作台（含批量处理）
    - HR终审工作台
### 4. 绩效调整管理
- **功能**：处理绩效过程中的调整申请。
- **子模块**：
    - 变更申请
    - 影响分析
    - 审批工作流
### 5. 绩效档案中心
- **功能**：存储和查询历史绩效数据。
- **子模块**：
    - 个人档案
    - 团队档案
    - 公司级分析
### 6. 系统配置
- **功能**：系统基础配置。
- **子模块**：
    - 角色权限管理
    - 部门绩效模式配置（强管控/协商模式）
    - 通知模板管理

## 三、数据库表结构设计
```sql
-- 核心表结构
CREATE TABLE `department` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `name` VARCHAR(50) NOT NULL COMMENT '部门名称',
  `performance_mode` ENUM('TOP_DOWN', 'BOTTOM_UP') NOT NULL DEFAULT 'TOP_DOWN' COMMENT '绩效模式'
) COMMENT='部门表';

CREATE TABLE `kpi_category` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `name` VARCHAR(50) NOT NULL COMMENT '分类名称',
    `parent_id` BIGINT DEFAULT 0 COMMENT '父分类ID',
    `department_id` BIGINT COMMENT '关联部门ID',
    `is_public` TINYINT(1) DEFAULT 0 COMMENT '是否公共分类'
) COMMENT='KPI分类表';

CREATE TABLE `kpi_template` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `code` VARCHAR(50) UNIQUE NOT NULL COMMENT '指标编码',
    `name` VARCHAR(100) NOT NULL COMMENT '指标名称',
    `formula` TEXT COMMENT '计算公式脚本',
    `data_source` ENUM('CRM','GITLAB','JIRA','MANUAL','ATTENDANCE') NOT NULL DEFAULT 'MANUAL' COMMENT '数据来源',
    `assessment_type` ENUM('QUANTITATIVE','QUALITATIVE') NOT NULL COMMENT '评定类型',
    `category_id` BIGINT NOT NULL COMMENT '分类ID',
    `weight_range_min` TINYINT DEFAULT 0 COMMENT '权重最小值',
    `weight_range_max` TINYINT DEFAULT 100 COMMENT '权重最大值',
    `version` INT DEFAULT 1 COMMENT '版本号',
    `is_active` TINYINT(1) DEFAULT 1 COMMENT '是否启用'
) COMMENT='KPI模板表';

CREATE TABLE `performance_plan` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `name` VARCHAR(100) NOT NULL COMMENT '计划名称',
    `cycle_type` ENUM('MONTHLY','QUARTERLY','HALF_YEARLY','YEARLY') NOT NULL,
    `start_date` DATE NOT NULL,
    `end_date` DATE NOT NULL,
    `department_id` BIGINT NOT NULL COMMENT '部门ID',
    `status` ENUM('DRAFT','ACTIVE','CLOSED') DEFAULT 'DRAFT' COMMENT '状态',
    `plan_mode` ENUM('AUTO','MANUAL') DEFAULT 'AUTO' COMMENT '拆解方式'
) COMMENT='考核计划表';

CREATE TABLE `employee_plan` (
     `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
     `employee_id` BIGINT NOT NULL COMMENT '员工ID',
     `plan_id` BIGINT NOT NULL COMMENT '计划ID',
     `plan_type` ENUM('ASSIGNED','NEGOTIATED') NOT NULL COMMENT '计划类型',
     `status` ENUM('DRAFT','SUBMITTED','APPROVED','REJECTED','ACTIVE') DEFAULT 'DRAFT' COMMENT '状态',
     `submitted_at` DATETIME COMMENT '提交时间',
     `approved_at` DATETIME COMMENT '批准时间',
     `total_weight` DECIMAL(5,2) DEFAULT 0.00 COMMENT '总权重'
) COMMENT='员工计划表';

CREATE TABLE `plan_kpi` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `employee_plan_id` BIGINT NOT NULL COMMENT '员工计划ID',
    `kpi_code` VARCHAR(50) NOT NULL COMMENT 'KPI编码',
    `weight` DECIMAL(5,2) NOT NULL COMMENT '权重',
    `target_value` VARCHAR(100) NOT NULL COMMENT '目标值',
    `split_values` JSON COMMENT '周期拆解值'
) COMMENT='计划指标表';

CREATE TABLE `negotiation_log` (
   `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
   `plan_kpi_id` BIGINT NOT NULL COMMENT '计划指标ID',
   `modified_field` ENUM('WEIGHT','TARGET','SPLIT') NOT NULL COMMENT '修改字段',
   `old_value` VARCHAR(100) NOT NULL COMMENT '原值',
   `new_value` VARCHAR(100) NOT NULL COMMENT '新值',
   `modified_by` BIGINT NOT NULL COMMENT '修改人',
   `modified_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
   `comments` TEXT COMMENT '修改原因'
) COMMENT='协商日志表';

CREATE TABLE `assessment_task` (
   `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
   `employee_plan_id` BIGINT NOT NULL COMMENT '员工计划ID',
   `current_stage` ENUM('SELF','MANAGER','HR','COMPLETED') DEFAULT 'SELF' COMMENT '当前阶段',
   `self_due_time` DATETIME COMMENT '自评截止时间',
   `manager_due_time` DATETIME COMMENT '上级评审截止',
   `status` ENUM('PENDING','IN_PROGRESS','COMPLETED') DEFAULT 'PENDING' COMMENT '任务状态'
) COMMENT='考核任务表';

CREATE TABLE `assessment_score` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `task_id` BIGINT NOT NULL COMMENT '任务ID',
    `kpi_code` VARCHAR(50) NOT NULL COMMENT 'KPI编码',
    `stage` ENUM('SELF','MANAGER','HR') NOT NULL COMMENT '评分阶段',
    `actual_value` VARCHAR(100) COMMENT '实际值',
    `score` DECIMAL(5,2) COMMENT '得分',
    `attachment` VARCHAR(200) COMMENT '附件路径',
    `comments` TEXT COMMENT '评语',
    `calculated_at` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '计算时间'
) COMMENT='评分表';

CREATE TABLE `tech_subjective_score` (
 `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
 `task_id` BIGINT NOT NULL COMMENT '任务ID',
 `dimension` ENUM('GOAL_COMPLETION','TECH_COMPLEXITY','COLLABORATION','INNOVATION') NOT NULL COMMENT '评分维度',
 `score` DECIMAL(5,2) NOT NULL COMMENT '得分',
 `comments` TEXT COMMENT '评语',
 `scored_by` BIGINT NOT NULL COMMENT '评分人'
) COMMENT='技术主观评分表';

CREATE TABLE `adjustment_request` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `task_id` BIGINT NOT NULL COMMENT '任务ID',
  `request_type` ENUM('KPI','WEIGHT','TARGET','SCORE') NOT NULL COMMENT '调整类型',
  `reason` TEXT NOT NULL COMMENT '调整原因',
  `old_data` JSON NOT NULL COMMENT '原数据快照',
  `new_data` JSON NOT NULL COMMENT '新数据',
  `status` ENUM('PENDING','APPROVED','REJECTED') DEFAULT 'PENDING' COMMENT '状态',
  `requested_by` BIGINT NOT NULL COMMENT '申请人',
  `requested_at` DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT='调整请求表';

CREATE TABLE `performance_summary` (
   `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
   `task_id` BIGINT UNIQUE NOT NULL COMMENT '任务ID',
   `objective_score` DECIMAL(5,2) COMMENT '客观分',
   `subjective_score` DECIMAL(5,2) COMMENT '主观分',
   `total_score` DECIMAL(5,2) NOT NULL COMMENT '总分',
   `rating` ENUM('A','B','C','D') COMMENT '评级',
   `report_path` VARCHAR(200) COMMENT '报告路径',
   `generated_at` DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT='绩效汇总表';

-- 索引优化
CREATE INDEX idx_plan_dept ON performance_plan(department_id);
CREATE INDEX idx_emp_plan ON employee_plan(employee_id, plan_id);
CREATE INDEX idx_task_stage ON assessment_task(current_stage);
CREATE INDEX idx_score_task ON assessment_score(task_id);
CREATE INDEX idx_adj_request ON adjustment_request(task_id, status);
```
## 四、关键设计说明
1. **双模式支持**：
    - 通过`department.performance_mode`字段区分部门模式。
    - 销售部门（TOP_DOWN模式）：
      - 使用`plan_kpi`表直接分配指标（`source='ASSIGNED'`）。
      - 领导在"目标下发中心"批量创建指标
      - 系统自动生成员工考核任务
      - 评分基于预设公式自动计算
    - 技术部门（BOTTOM_UP模式）：
      - 员工通过`personal_plan`提报计划，经协商后确定指标（`source='NEGOTIATED'`）。
      - 员工在"我的自评工作台"创建个人计划
      - 通过"计划协商中心"与领导达成一致
      - 评分 = 客观分（60%）+ 主观分（40%）
2. **协商过程记录**：
    - `negotiation_log`表记录每次指标调整的详细过程，确保可追溯。
    - 每次修改包含：
      - 修改字段（权重/目标值/拆解比例）
      - 修改前后的值
      - 修改人和时间戳
3. **评分差异化**：
    - 技术部门使用`leadership_score`存储领导在四个维度的主观评分。
      - 目标完成度（30%）
      - 技术复杂度（25%）
      - 协作贡献（25%）
      - 创新价值（20%）
    - 每个维度提供评分标准和案例参考
    - 绩效汇总时，客观分（公式计算）占60%，主观分占40%。
4. **预审规则**：
    - 在计划提交时，系统自动检查目标值是否在合理范围（如历史均值的0.8~1.5倍），异常情况自动标记。
5. **批量处理**：
    - 领导工作台提供矩阵视图，可同时查看多个员工的目标，并支持批量调整。
6. **智能减负设计**
      graph TD
      A[员工提交计划] --> B{系统预审}
      B -->|正常| C[自动归档]
      B -->|异常| D[标记预警]
      D --> E[领导重点处理]
      E --> F[批量调整工具]
      F --> G[一键确认]
7. 性能优化措施
    - 数据分区：按考核周期分区存储历史数据
   - 预聚合：定时任务预计算团队汇总数据
   - 读写分离：评分操作使用只读副本
   - 缓存策略：高频访问的KPI模板缓存24小时
## 五、后期维护建议
1. **数据归档**：定期将历史考核数据迁移到历史库，保证主库性能。
```sql
-- 每年1月归档上年度数据
CREATE EVENT archive_performance_data
ON SCHEDULE EVERY 1 YEAR STARTS '2024-01-01 02:00:00'
DO
BEGIN
  -- 将上年度数据迁移到归档库
  INSERT INTO archive_db.performance_summary
  SELECT * FROM performance_summary
  WHERE YEAR(generated_at) = YEAR(CURDATE()) - 1;
  
  -- 清理主库历史数据
  DELETE FROM performance_summary
  WHERE YEAR(generated_at) = YEAR(CURDATE()) - 1;
END;
```
2. **公式引擎**：`kpi_pool.formula`字段存储的脚本建议使用沙箱环境执行，确保安全。
3. **权限控制**：维护好角色权限表，确保数据隔离（员工只能访问自己的数据）
