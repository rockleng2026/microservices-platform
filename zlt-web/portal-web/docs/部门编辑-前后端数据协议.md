# 部门编辑功能 - 前后端数据协议

## 📡 API接口：`POST /api/organization/departments/save`

### 🔍 操作类型识别

前端现在会在请求数据中明确标识操作类型，后端应根据此信息进行不同的验证逻辑：

#### 1. 新增部门操作
```json
{
  "name": "新部门名称",
  "depNo": "DEPT001", 
  "parentId": 1,
  "directorId": 5,
  "gradeid": 2,
  "tel": "010-12345678",
  "address": "北京市朝阳区",
  "description": "部门描述",
  "status": 1,
  "operationType": "add"  // 🔑 关键标识：新增操作
  // 注意：新增时没有 id 字段
}
```

#### 2. 编辑部门操作
```json
{
  "id": 123,               // 🔑 关键字段：要编辑的部门ID
  "name": "修改后的部门名称",
  "depNo": "DEPT001",      // 可能保持不变，也可能修改
  "parentId": 2,
  "directorId": 8,
  "gradeid": 2,
  "tel": "010-87654321",
  "address": "北京市海淀区",
  "description": "修改后的描述",
  "status": 1,
  "operationType": "edit"  // 🔑 关键标识：编辑操作
}
```

## 🛠️ 后端验证逻辑建议

### 当前问题分析
位置：`@zlt-business/organization-service/src/main/java/com/central/organization/service/impl/DepartmentServiceImpl.java`
方法：`saveDepartment`

### 建议的验证逻辑

```java
public void saveDepartment(Department department) {
    // 1. 根据操作类型和ID判断操作类型
    boolean isEdit = department.getId() != null || "edit".equals(department.getOperationType());
    
    if (isEdit) {
        // 编辑操作：验证部门编号时排除当前部门
        validateDeptNoForEdit(department.getDepNo(), department.getId());
        validateDeptNameForEdit(department.getName(), department.getParentId(), department.getId());
    } else {
        // 新增操作：正常验证唯一性
        validateDeptNoForAdd(department.getDepNo());
        validateDeptNameForAdd(department.getName(), department.getParentId());
    }
    
    // 其他业务逻辑...
}

private void validateDeptNoForEdit(String depNo, Long excludeId) {
    // 查询除了当前部门ID外，是否有其他部门使用相同编号
    long count = departmentMapper.countByDepNoExcludeId(depNo, excludeId);
    if (count > 0) {
        throw new BusinessException("部门编号已存在");
    }
}

private void validateDeptNoForAdd(String depNo) {
    // 查询是否有任何部门使用此编号
    long count = departmentMapper.countByDepNo(depNo);
    if (count > 0) {
        throw new BusinessException("部门编号已存在");
    }
}
```

## 📊 数据验证规则

| 字段 | 新增验证 | 编辑验证 | 说明 |
|------|---------|---------|------|
| `depNo` | 全局唯一 | 排除当前ID的唯一性 | 部门编号 |
| `name` | 同级唯一 | 排除当前ID的同级唯一性 | 部门名称 |
| `parentId` | 有效性检查 | 有效性检查 + 不能设为自己或子部门 | 上级部门 |
| `gradeid` | 层级合理性 | 层级合理性 | 部门等级 |

## 🔧 SQL查询示例

### 部门编号验证（编辑时）
```sql
-- 检查除当前部门外是否有相同编号
SELECT COUNT(*) FROM departments 
WHERE dep_no = #{depNo} 
AND id != #{excludeId}
AND deleted = 0
```

### 部门编号验证（新增时）
```sql
-- 检查是否有相同编号
SELECT COUNT(*) FROM departments 
WHERE dep_no = #{depNo}
AND deleted = 0
```

## 🚨 常见错误场景

### 1. 错误的验证逻辑
```java
// ❌ 错误：编辑时也检查了自己
if (departmentMapper.countByDepNo(depNo) > 0) {
    throw new BusinessException("部门编号已存在");
}
```

### 2. 正确的验证逻辑
```java
// ✅ 正确：编辑时排除自己
if (department.getId() != null) {
    // 编辑操作
    if (departmentMapper.countByDepNoExcludeId(depNo, department.getId()) > 0) {
        throw new BusinessException("部门编号已存在");
    }
} else {
    // 新增操作
    if (departmentMapper.countByDepNo(depNo) > 0) {
        throw new BusinessException("部门编号已存在");
    }
}
```

### 测试场景

```json
{"name": "测试部", "depNo": "TEST001", "operationType": "add"}
```

#### 2. 新增部门 - 应该失败（编号重复）
```json
{"name": "新技术部", "depNo": "TECH001", "operationType": "add"}
```

#### 3. 编辑部门 - 应该成功（保持原编号）
```json
{"id": 1, "name": "技术部门", "depNo": "TECH001", "operationType": "edit"}
```

#### 4. 编辑部门 - 应该失败（改为其他部门的编号）
```json
{"id": 1, "name": "技术部门", "depNo": "HR001", "operationType": "edit"}
```
