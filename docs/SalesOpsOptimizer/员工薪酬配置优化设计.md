# 员工薪酬配置优化设计

## 1. 业务逻辑优化

### 1.1 核心思路
员工薪酬配置表的展现列表逻辑，由盈策通决策模块后台提供接口。接口先调用组织模块的员工列表接口，获取到员工列表数据，再通过员工ID关联 `soo_employee_salary_config` 表获取薪酬配置。界面逻辑参考组织模块员工管理的列表界面，上面有搜索框，下面是员工列表，所有的接口都从盈策通决策模块封装一次组装数据后提供。

### 1.2 数据整合方式
- **主数据源**: 组织模块员工列表 (Employee)
- **扩展数据**: 员工薪酬配置 (soo_employee_salary_config)
- **职级标准**: 职级薪资标准表 (soo_job_level_salary) - 提供工资范围和绩效范围
- **关联逻辑**: 
  - 员工基础信息 通过员工ID关联
  - 薪酬配置 通过employee_id关联
  - 职级标准 通过job_level_id关联获取工资范围
- **数据组装**: 在SOO服务层统一组装，返回完整的员工薪酬信息

前端页面的职级标准改成职位职级标准，这一列改成4列，4列的值来源原职位职级配置表的4个字段
`base_salary_min` decimal(10,2) NOT NULL COMMENT '基础工资下限',
`base_salary_max` decimal(10,2) NOT NULL COMMENT '基础工资上限',
`performance_ratio_min` decimal(5,4) NOT NULL COMMENT '绩效比例下限',
`performance_ratio_max` decimal(5,4) NOT NULL COMMENT '绩效比例上限',
关联条件是position_id

这里有2个关联，一个是关联soo_job_level_salary获取这个职位的职级标准范围(基础工资范围、绩效范围)，另外一个是关联获取主表员工表的数据然后通过员工id关联soo_employee_salary_config的对这个员工薪资配置数据的关联
对了那前面oo_employee_salary_config表结构中的job_level_id这个字段就没有必要了，我手动手改表结构，你请根据最新的结构修改代码


### 1.3 职级关联设计
```
Employee (组织服务) 
    ↓ (employee_id)
soo_employee_salary_config (薪酬配置)
    ↓ (job_level_id) 
soo_job_level_salary (职级标准) → 获取基础工资范围、绩效比例范围
```

## 2. 表结构设计

### 2.1 员工薪酬配置表结构
```sql
-- ===================================================================
-- 员工薪酬配置表 (优化版)
-- ===================================================================
CREATE TABLE `soo_employee_salary_config` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `employee_id` bigint(20) NOT NULL COMMENT '员工ID',
  `base_salary` decimal(10,2) NOT NULL COMMENT '基础工资',

  `is_sales_incentive` tinyint(1) DEFAULT 0 COMMENT '是否参与销售提成(1是,0否)',

  `is_department_bonus` tinyint(1) DEFAULT 0 COMMENT '是否参与部门分红(1是,0否)',
  `sales_incentive_ratio` decimal(6,2) DEFAULT 0 COMMENT '销售提成比例-%号单位',
  `team_incentive_ratio` decimal(6,2) DEFAULT 0 COMMENT '团队提成比例-%号单位',
  `effective_date` date NOT NULL COMMENT '生效日期',
  `expire_date` date COMMENT '失效日期',
  `status` tinyint(1) DEFAULT 1 COMMENT '状态(1启用,0禁用)',
  `remark` varchar(500) COMMENT '备注',
  `created_at` timestamp DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `created_by` bigint(20) COMMENT '创建人',
  `updated_by` bigint(20) COMMENT '更新人',
  `tenant_id` varchar(32) DEFAULT 'default' COMMENT '租户ID',
  `delflag` tinyint(1) DEFAULT 0 COMMENT '删除标识',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_employee_effective` (`employee_id`, `tenant_id`),
  KEY `idx_employee_id` (`employee_id`),
  KEY `idx_tenant_id` (`tenant_id`),
  KEY `idx_status` (`status`, `delflag`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='员工薪酬配置表';
```

### 2.2 职级薪资标准表 (关联表)
```sql
CREATE TABLE `soo_job_level_salary` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `department_id` bigint(20) NOT NULL COMMENT '部门ID-关联部门表',
  `position_id` bigint(20) NOT NULL COMMENT '岗位ID-关联岗位表',
  `job_level_code` varchar(50) NOT NULL COMMENT '职级编码-编码定义在通用字典表',
  `base_salary_min` decimal(10,2) NOT NULL COMMENT '基础工资下限',
  `base_salary_max` decimal(10,2) NOT NULL COMMENT '基础工资上限',
  `performance_ratio_min` decimal(5,4) NOT NULL COMMENT '绩效比例下限',
  `performance_ratio_max` decimal(5,4) NOT NULL COMMENT '绩效比例上限',
  `effective_date` date NOT NULL COMMENT '生效日期',
  `expire_date` date DEFAULT NULL COMMENT '失效日期',
  `status` tinyint(1) DEFAULT '1' COMMENT '状态(1启用,0禁用)',
  `sort_order` int(11) DEFAULT '0' COMMENT '排序号',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `created_by` bigint(20) DEFAULT NULL COMMENT '创建人',
  `updated_by` bigint(20) DEFAULT NULL COMMENT '更新人',
  `tenant_id` varchar(32) DEFAULT 'default' COMMENT '租户ID',
  `delflag` tinyint(1) DEFAULT '0' COMMENT '删除标识',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_job_level_dept` (`position_id`,`tenant_id`),
  KEY `idx_department_id` (`department_id`),
  KEY `idx_effective_date` (`effective_date`),
  KEY `idx_tenant_id` (`tenant_id`),
  KEY `idx_status` (`status`,`delflag`)
) ENGINE=InnoDB  DEFAULT CHARSET=utf8mb4 COMMENT='职位职级薪资标准表';
```

### 2.3 表结构关联说明
1. **保留字段**: `job_level_id` - 关联 `soo_job_level_salary.id`
2. **移除字段**: `employee_name`, `employee_no`, `department_id`, `position_id` (通过组织服务获取)
3. **数据关联**: 
   - 员工基础信息通过Feign调用组织服务获取
   - 职级信息通过job_level_id关联soo_job_level_salary表获取工资范围
   - 地区信息通过字典服务获取

### 4.2 数据校验逻辑
1. **工资范围校验**: 基础工资必须在职级标准的min-max范围内
2. **绩效比例校验**: 如果配置了绩效，比例必须在职级标准范围内
3. **唯一性校验**: 同一员工+生效日期不能重复
4. **日期校验**: 生效日期不能早于当前日期

```java
// 1. 查询员工列表(组织服务)
List<Employee> employees = employeeFeignClient.getEmployees(query);

List<EmployeeSalaryVO> result = assembleEmployeeSalaryData(employees, salaryConfigs, jobLevelSalaries);
```

### 5.2 工资范围校验
```java
public boolean validateSalaryRange(Long jobLevelId, BigDecimal baseSalary) {
    JobLevelSalary jobLevel = jobLevelSalaryService.getById(jobLevelId);
    if (jobLevel == null) {
        return false;
    }
    return baseSalary.compareTo(jobLevel.getBaseSalaryMin()) >= 0 
        && baseSalary.compareTo(jobLevel.getBaseSalaryMax()) <= 0;
}
```

## 6. 技术实现要点

### 6.1 数据关联优化
- 使用批量查询减少数据库访问
- 关联查询优化，避免N+1问题
- 合理使用缓存提升性能

### 6.2 前端交互优化
- 职级选择时实时显示工资范围
- 基础工资输入时实时校验范围
- 超出范围时给出明确提示

### 6.3 业务逻辑
- 职级变更时需要重新配置薪酬
- 薪酬历史记录保留，支持查看变更轨迹
- 支持批量调整和导入导出功能
